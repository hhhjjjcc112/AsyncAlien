第4章x86_64移植与实现细节

本章描述将系统从RISC-V迁移到x86_64时的实现要点，聚焦启动与早期初始化、percpu与FPU/APIC初始化、trap/syscall的切换语义、页表与寄存器差异、以及ACPI/PCI的探测方法。每个要点下都嵌入示例代码以说明实现要领，示例为说明性伪代码，不指向或引用任何仓库路径。

4.1 启动与percpu布局

x86_64的早期启动需完成控制寄存器与长模式相关配置，并在链接期为per-cpu区与trampoline预留连续映像。percpu的初始化包含就地构造每核数据区并设置per-cpu寄存器镜像，以便在陷阱/系统调用时通过GS快速访问。下面给出真实实现的关键片段作为示例，并对要点做更详细的解释。

4.2 FPU与APIC的初始化

每个CPU在进入内核运行之前，需要先把FPU和本地APIC准备好。FPU部分先清除CR0中的模拟位和任务切换位，再打开CR4中的相关支持位，最后执行fninit把x87状态复位到初始值，这样后续浮点指令才能在已知状态下工作。APIC部分则先在BSP上关闭旧式8259A PIC，再判断CPU是否支持x2APIC，如果支持就走MSR方式配置本地APIC，如果不支持就回退到MMIO方式。初始化完成后，把APIC上下文保存起来，供后续CPU和中断子系统直接使用。这样做可以让每个CPU在更早阶段拥有稳定的浮点环境和中断入口，也能减少后面处理中断时的额外判断。


4.3 中断控制、percpu与syscall入口

下面首先给出trap的汇编入口与简要说明，这段代码为内核统一的异常/中断入口。代码在trampoline段中定义，各个异常向量最终会跳转到.Ltrap_common以统一保存寄存器并判定来源。

.section .text.trampoline
.code64

.macro DEF_HANDLER, i
.Ltrap_handler_\i:
.if \i == 8 || (\i >= 10 && \i <= 14) || \i == 17
    push \i
    jmp .Ltrap_common
.else
    push 0
    push \i
    jmp .Ltrap_common
.endif
.endm

.Ltrap_common:
    push rax
    push rcx
    push rdx
    push rdi
    push rsi
    push r8
    push r9
    push r10
    push r11
    push rbx
    push rbp
    push r12
    push r13
    push r14
    push r15
    sub rsp, 2 * 8
    mov rax, [rsp + TF_CS]
    and rax, 0x3
    cmp rax, 0x3
    je .Lfrom_user
    /* kernel-origin exception path */
    /* restore stack and jump to kernel handler */
    jmp .Lkernel_handler
.Lfrom_user:
    /* user-origin exception path */
    swapgs
    /* 在这里使用GS访问percpu区域以保存用户上下文、切换栈和CR3等 */
    /* 之后调用上层Rust处理函数，处理完成后恢复并iretq */
    jmp .Luser_common

/* 说明：上述汇编首先为每个异常构造入口，统一把寄存器保存到栈上，
   并通过检查CS的DPL位判断是否来自用户态。若来自用户态，先swapgs
   切换到内核的GS基址，再使用GS偏移访问percpu保存用户rsp等上下文，
   最后切换到内核栈并调用上层处理函数。若来自内核态，则直接进入内核处理路径并最终通过iretq返回。*/

为了在用户地址空间下仍然能在syscall中访问percpu数据，内核在所有虚拟地址空间的高地址映射一份percpu镜像，并在初始化时把percpu寄存器设为该镜像的基址。这样在切换地址空间时，不需要修改GS的值，就能正确访问percpu数据。

表4-5 percpu镜像写入与LSTAR/SFMask设置

// 在 syscall 初始化时把 GS 指向 percpu 镜像高地址
let gs_value = percpu::read_percpu_reg();
let gs_mirror = PERCPU_MIRROR_BASE - _percpu_start as *const () as usize + gs_value;
unsafe { percpu::write_percpu_reg(gs_mirror); }

// 设置 syscall 相关 MSR，将快速入口指向 trampoline 内的 syscall_entry
let lstar_offset = syscall_entry as *const () as usize - strampoline as *const () as usize;
let lstar = VirtAddr::new((TRAMPOLINE + lstar_offset) as u64);
LStar::write(lstar);
// 屏蔽 TF/IF/DF/IOPL/NT/AC，避免带入用户态标志位。
let sfmask = RFlags::TRAP_FLAG
        | RFlags::INTERRUPT_FLAG
        | RFlags::DIRECTION_FLAG
        | RFlags::IOPL_LOW
        | RFlags::IOPL_HIGH
        | RFlags::NESTED_TASK
        | RFlags::ALIGNMENT_CHECK;
SFMask::write(sfmask);
unsafe { Efer::write(Efer::read() | EferFlags::SYSTEM_CALL_EXTENSIONS); }

上述代码片段在内核虚拟地址空间为percpu数据建立一个稳定且可由汇编访问的高地址镜像，并将该镜像地址写入寄存器镜像或相关MSR，保证swapgs后汇编可以通过GS快速定位。与此同时，将LSTAR设置为trampoline中的syscall入口地址，使得用户态的syscall指令会直接跳入内核预期的trampoline代码段。SFMask的配置则用于屏蔽sysret/syscall交替过程中不应被继承的标志位，避免返回时出现安全漏洞。

    swapgs
    mov qword ptr gs:[offset __PERCPU_USER_RSP], rsp
    mov rsp, qword ptr gs:[offset __PERCPU_TSS + {tss_rsp0_offset}]
    sub rsp, 8

trap和syscall最终都进入同一套中断控制流程。trap入口先把通用寄存器压栈，再通过检查CS.DPL判断来自用户态还是内核态。来自用户态时，流程先swapgs，再切换CR3和栈，然后进入上层处理函数；来自内核态时，则直接走内核处理逻辑，最后通过iretq返回。把syscall和trap放在同一节里描述，可以更清楚地说明它们共享的保存寄存器、切换地址空间和恢复现场这些步骤，也能看出它们在入口和返回上的差异只是一小部分。

镜像percpu数据在syscall中的用法如上述代码所示。该汇编实现通过swapgs切换到内核GS基址，然后将用户rsp暂存到percpu区，取出TSS中的rsp0，最后保存用户rsp到栈上，实现用户rsp和TSS.rsp0的交换。syscall路径中不需要保存ss，error code和vector，因此跳过这些部分，而r11和rcx分别被rflags和rip覆盖，需要按rflags和rip的位置保存。接下来的步骤就与trap处理类似了。syscall返回时，需要将trap上下文中的rflags和rip分别恢复到r11和rcx上，并直接将用户rsp的值恢复到rsp，不需要借助percpu区域。最后通过sysretq返回用户态。


4.4 x86_64与RISC-V的页表结构與寄存器差异

x86_64使用四级页表（PML4→PDPT→PD→PT），每级512项，索引宽度为9位。CR3保存页表根的物理地址，CR2保存页错误地址，CR4控制若干特性，EFER控制系统调用相关扩展。实现时应提供统一的页表抽象以在不同架构之间映射语义。下面给出page-table库中对索引计算的真实摘录与CR3读写的实现。

const fn p4_index(vaddr: VirtAddr) -> usize {
    (vaddr.as_usize() >> (12 + 27)) & (ENTRY_COUNT - 1)
}

pub fn read_cr3() -> usize {
    let (frame, _) = control::Cr3::read();
    frame.start_address().as_u64() as usize
}

CR3保存页表根帧的物理地址，内核在进行地址空间切换时需要读写CR3。切换CR3会导致TLB对应条目的无效化（或在某些实现下需要显式刷新），因此实现必须在切换后采取必要的同步与缓存刷新措施，尤其是在处理跨用户/内核页表隔离和处理设备DMA时要确保一致性。

4.5 域加载的架构无关与架构相关分层

域加载阶段把内核引导过程中需要用到的驱动和服务按预定义列表逐个加载并注册。这个过程分成两层：架构无关层处理所有平台共用的加载逻辑，架构相关层定义各自平台的特定域。架构无关层在init_domains()中实现，主要职责是读取初始化RAM盘(initrd)中gzip压缩的数据，解压后遍历CPIO档案格式的内容，查找所有域对应的ELF二进制文件（文件名前缀为g），然后依次调用register_domain_elf把这些ELF加载并注册。这层首先注册COMMON_INIT_DOMAIN_LIST中定义的通用域，包括缓冲UART、缓冲输入、块设备缓存、设备文件系统、FAT文件系统、管道文件系统、进程文件系统、内存文件系统、系统文件系统、调度器、任务管理、虚拟文件系统和网络栈等，这些域与具体硬件平台无关，所以代码和逻辑在所有架构上保持一致。

架构相关层由各架构的ARCH_INIT_DOMAIN_LIST定义，在x86_64上包括uart16550串口、virtio块设备、本地APIC域、IO APIC域、CMOS RTC、virtio网络、virtio输入、virtio图形和回环网络等，这些域对应x86_64特有的中断控制器和设备驱动。相比之下，riscv64上的ARCH_INIT_DOMAIN_LIST包括goldfish RTC、PLIC中断控制器、QEMU上的uart16550和virtio设备、以及VisionFive 2平台上的uart8250和SD卡控制器，反映了该架构的不同硬件特征。init_domains()在注册完通用域后，随即遍历ARCH_INIT_DOMAIN_LIST并调用相同的register_domain_elf函数注册这些架构特定的域。这样的分层设计保证了通用部分在所有架构上维护一份代码，同时允许各架构在域列表层面灵活定制自己需要的驱动和服务，避免了在通用加载逻辑中散布平台判断条件。

4.8 本章小结

本章给出了从RISC-V向x86_64迁移时的实现细节并以真实代码摘录作为佐证。主要结论如下：
- percpu的就地初始化与高地址镜像是保证trap与syscall路径低延迟访问per-cpu数据的关键；
- FPU的寄存器位与指令集支持需要在每核早期启用，且任务切换处要对浮点上下文进行显式保存/恢复；
- APIC的基址與IOAPIC条目应以ACPI为权威来源，缺失时采用兜底策略；
- 在用户页表隔离场景下，trampoline需要提供稳定的可执行入口区（trampoline段）并通过swapgs/GS访问per-cpu镜像以完成安全的CR3/栈切换；
- 页表抽象应兼顾大页支持以减少TLB压力，并在页表根切换时注意刷新缓存与TLB；
- PCI枚举优先使用MCFG/ECAM，MCFG信息不完整时应有合理的回退與警告策略。
