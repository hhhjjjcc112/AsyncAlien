# 第1章 引言

## 1.1 研究背景与意义

随着计算机系统功能日益复杂，Linux内核代码库规模不断增长。传统宏内核架构将操作系统的大部分功能集中在单一的受信执行环境中，使得任何一个功能模块中的缺陷都可能危及整个系统的安全性和可靠性。多个真实漏洞的经验表明，传统内核的复杂性不仅体现为代码行数和逻辑耦合的上升，更表现为漏洞修复成本高、验证难度大、攻击面广而难以控制。

为应对上述风险，Linux内核社区提出了严格的内核内存权限控制、KASLR、seccomp、模块签名等防御手段。这些机制有效提高了攻击门槛，但其本质仍是对复杂系统的被动补救，难以从根本上降低内核复杂性带来的结构性风险。隔离式内核架构由此成为另一条路径：通过把系统功能划分为相对独立的故障隔离域，各域通过明确接口交互，避免直接共享内核内存，从而将故障影响局限在域内并减少可被触达的内核路径。近年来Linux生态中多起CVE事件也再次说明，高复杂度核心路径一旦失守，影响范围往往跨越模块边界。

在这种架构下，系统具备如下优势：

1. 故障局限化：单个域的漏洞或故障不会波及整个系统
2. 攻击面缩减：每个域只暴露必要的接口，减少高风险路径
3. 独立演进：功能模块可独立升级或替换，降低系统整体变更成本
4. 隔离边界明确：安全属性更易于验证与审计

Alien是基于域隔离理念的内核实现，已在RISC-V平台验证了隔离域、共享堆通信与域加载等机制。x86-64平台在启动、异常处理、内存和设备管理等方面与RISC-V存在显著差异，要求在平台抽象层做出相应适配。与此同时，系统调用、时间查询等高频路径对性能尤为敏感，传统Linux通过vDSO在用户态提供快速路径以降低开销。Alien中的vDSO、协作调度与驱动域复用等设计亦位于这条关键路径之上，其设计合理性直接影响系统可用性。

## 1.2 研究目标与问题陈述

研究目标方面，本项目在不破坏现有RISC-V路径的前提下，建立x86-64可运行链路，使系统能够完成启动、早期初始化、设备发现、域加载、多核启动并进入用户态；同时为vDSO、协作调度等高频机制预留清晰的扩展接口，确保最小可运行版本具备后续优化空间。

围绕上述目标，研究问题主要包括以下三类：

1. 架构差异的统一抽象：如何统一抽象启动流程、内存布局、中断控制器与设备发现等差异，使x86-64与RISC-V之间实现尽可能多的代码复用且保持语义正确。
2. 高频路径的跨架构归一：如何统一vDSO、系统调用入口与上下文切换等高频路径设计，在兼容用户ABI的前提下降低跨架构分叉。
3. 设备机制的兼容与边界控制：如何在设备发现与驱动注册中兼容ACPI、PCI、UART、VirtIO等机制，同时保持驱动域与内核职责边界清晰。

研究范围聚焦于上述问题在x86-64平台上的实现与验证，通过启动链路、功能正确性、隔离性、恢复性和性能开销等维度说明迁移后的系统不仅可启动，而且具备实际可用性。

## 1.3 主要贡献点

本项目的主要贡献包括：

1. 完成Alien从RISC-V到x86-64的系统性迁移方案，覆盖启动、内存管理、中断与异常、系统调用、任务切换和设备发现等关键路径的架构适配。
2. 提出并实现统一的平台抽象层，将架构差异收敛到平台层与少量架构代码中，为跨架构复用提供清晰骨架。
3. 完成vDSO的设计与系统集成，建立vvar机制、快速路径与回退机制之间的协作关系。
4. 构建覆盖功能正确性、隔离性、恢复性与性能开销的验证框架，以多维度证据说明系统的实际可用性而非仅存在性。
