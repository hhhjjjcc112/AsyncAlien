## 1. 引言（预计完成：2026-05-12）
1. 研究背景与意义
  - 传统内核逐渐积累复杂性，导致代码路径耦合加深、漏洞和故障影响面扩大，修改成本持续上升。
  - Alien将内核功能拆分为多个故障隔离域，降低模块故障对整体系统的影响
  - 现有Alien设计已验证了域隔离、共享堆通信、域加载等机制的可行性，但其最初实现主要面向RISC-V平台
  - x86-64平台具有更复杂的实现，迁移过程需要重构平台抽象
  - vDSO、协作调度、驱动域复用等机制位于用户/内核边界的关键路径，既影响系统调用与时间获取等高频操作的性能，也决定了域隔离方案能否在实际场景中保持可用性。
  - 因此，研究Alien在x86-64平台上的移植与演进，不仅有助于验证其架构抽象的可迁移性，也能为多架构隔离内核的设计提供实现经验与工程依据。
2. 研究目标与问题陈述：
  - 目标
     - 在不破坏现有RISC-V路径的前提下，建立x86-64可运行链路，使系统能够完成启动、设备发现、域加载、多核启动、进入用户态
     - 为vDSO、协作调度预留接口，使系统能够在保证最小可运行的同时具备继续改进的空间
  - 问题
    - 如何抽象启动流程、内存布局、中断控制器、设备发现和系统调用入口，使x86-64与RISC-V共用尽可能多的代码，同时维持各自语义正确。
    - 如何将vDSO、syscall归一化与用户态ABI适配纳入统一设计，减少高频路径上的架构分叉。
    - 如何在设备发现与驱动注册中兼容ACPI、PCI、UART、VirtIO等不同机制，并保持驱动域与kernel的职责边界清晰。
3. 主要贡献点：
  - 完成Alien从RISC-V到x86-64的系统性迁移方案，梳理并实现启动、内存管理、中断、系统调用、任务切换与设备发现等关键路径的架构适配。
  - 提出并实现平台抽象，将架构相关差异收纳到平台层和少量arch代码中，形成可同时支持riscv64与x86-64的公共实现骨架。
  - 完成vDSO的设计与集成，建立vvar、快速路径与回退机制之间的协作关系，为高频系统服务提供低开销入口。
  - 建立一套覆盖功能正确性、隔离性、恢复性与性能开销的验证框架，用于说明迁移后的系统不仅可启动，而且具备实际可用性。

## 2. 背景与相关工作（预计完成：2026-05-12）
1. 原始Alien系统综述
  - 介绍Alien的基本理念，将内核功能拆分为多个职责清晰的隔离域，并通过显式接口进行交互
  - 概述Alien的域组织方式
  - Alien实现背景主要面向RISC-V，因此其启动流程、trap入口、内存布局和设备发现方式都带有明显的平台假设。
2. 相关工作
  - 与微内核的对比
  - Rust语言的安全性
  - vdso的设计与应用

## 3. 系统架构与设计（预计完成：2026-05-12）
1. 总体架构
  - 系统分层为 boot → loader → 域加载 → 用户进程
  - 核心模块：域管理、镜像加载、共享堆通信
2. 平台抽象策略
  - platform定义统一的公共接口统一启动、中断、内存初始化
  - 具体实现按架构分开，x86_64 和 riscv64 各有平台层
  - 内存发现机制统一接口，x86_64 从 Multiboot 获取，riscv64 用各自方式
  - 设备发现 x86_64 走 ACPI 和 PCI，riscv64 走原有路径
  - 平台配置文件按架构分开维护
3. 域隔离与通信模型
  - 域间隔离通过独立镜像、共享堆、显式接口实现
  - 通信方式包括 RPC 和共享内存
  - 高速路径（系统调用、时间查询）需特殊优化

## 4. x86-64移植与实现（预计完成：2026-05-13）
1. 启动与早期初始化
  - 通过 Multiboot 启动，完成入口跳转和早期 BSS 清零。
  - 先做主核初始化，再完成 FPU/SSE、时间子系统和 APIC 的准备。
  - 从启动信息里解析内存、initrd 和启动参数，形成机器信息。
  - 拉起从核并等待同步完成，再放行后续调度。
2. 中断与异常子系统
  - 建立中断/异常入口和路由，让 trap 能正确进入、分发和返回。
  - 先完成中断控制器初始化，再接入系统调用和用户态返回链路。
3. 任务切换与系统调用
  - 统一 syscall 入口和上下文切换，保证用户态调用能被正确处理。
  - 保持任务上下文和返回路径一致，避免切换后状态错乱。
4. 虚拟内存与ABI兼容
  - 设计地址空间隔离和 trampoline 映射，保证内核和用户态分开。
  - 兼顾 Linux ABI 的兼容性和切换开销，先保证最小可用链路。
5. 设备发现与域加载流程
  - 设备发现先完成，再进入域加载和 vDSO 初始化，保证内核主流程能顺下来。
  - 主核完成后统一拉起从核，等待同步后再进入正常运行阶段。

## 5. 隔离域实现与vdso机制（预计完成：2026-05-13）
1. 域镜像构建与运行时加载

2. 驱动域组织与复用

3. 功能域实现
  - 简要划分 Task、VFS、syscall、vDSO 等域的职责与交互边界。
4. vDSO与协作调度机制
  - 提供低开销的用户态快速路径，并与调度机制协同减少系统调用开销。
5. 隔离性验证设计
  - 设计故障注入与权限检查用例，评估隔离效果与恢复能力。
